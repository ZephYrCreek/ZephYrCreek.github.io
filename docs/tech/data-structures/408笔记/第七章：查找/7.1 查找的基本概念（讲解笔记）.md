# 7.1 查找的基本概念（讲解笔记）

::: info 本节要解决的问题
学习具体的查找算法之前，先建立一套共同语言：什么是查找，数据放在哪里查，依据什么查，以及怎样衡量一次查找的效率。
:::

## 1. 什么是查找

**查找（Search）**是指在一个数据集合中，寻找满足某种条件的数据元素的过程。

查找有两种基本结果：

- **查找成功**：集合中存在满足条件的数据元素，并且已经找到它。
- **查找失败**：集合中不存在满足条件的数据元素。

例如，有一张学生信息表：

| 学号 | 姓名 | 成绩 |
| --- | --- | ---: |
| 1001 | 张三 | 85 |
| 1002 | 李四 | 92 |
| 1003 | 王五 | 78 |
| 1004 | 赵六 | 90 |

查找学号为 `1003` 的学生时，可以找到王五，查找成功；查找学号为 `1005` 的学生时，表中没有对应记录，查找失败。

这里要注意：查找时通常不是输入完整记录，而是根据记录中的某个数据项定位整条记录。例如，用学号找到学生后，可以得到姓名、成绩等全部信息。

### 查找的两个核心问题

一次查找总要回答两个问题：

1. **判断条件是什么？** 怎样确认当前元素就是目标？
2. **寻找策略是什么？** 按什么顺序、用什么方法接近目标？

第一个问题引出“关键字”，第二个问题引出后续的顺序查找、折半查找等算法。

## 2. 什么是查找表

**查找表（Search Table）**是用于查找的数据集合，由同一类型的数据元素或记录组成。

上面的学生信息表就是一张查找表，其中每一行都是一条学生记录。围绕查找表，常见操作包括：

- 查询某个特定的数据元素；
- 检索某个数据元素的属性；
- 插入新的数据元素；
- 删除已有的数据元素。

为什么要专门定义“查找表”？因为查找效率不仅取决于要找什么，还取决于数据怎样组织和存储。

例如，同样查找学号 `1003`：

- 如果数据无序，只能考虑逐个检查；
- 如果数据按学号有序，就可以利用大小关系缩小范围。

因此，查找算法与查找表的组织方式密切相关。

## 3. 静态查找表与动态查找表

区分二者的标准不是“数据是否放在静态内存中”，而是：**操作过程中是否需要修改数据集合。**

### 3.1 静态查找表

静态查找表只进行查询，不在查找过程中插入或删除元素。

例如，一份已经确定的考试成绩名单，只供查询，不再增删学生记录。

这种场景主要关注：怎样组织数据，才能使查询更快。

### 3.2 动态查找表

动态查找表除了查询，还需要支持插入或删除元素。

例如，学校的信息系统既要查询学生信息，也要录入新生、删除已离校学生的记录。

这时不能只看查找速度，还要同时考虑插入、删除的代价。某种结构即使查找很快，如果每次修改都非常麻烦，也未必适合动态场景。

::: warning 判断方法
“静态”与“动态”描述的是查找表需要支持的操作，不是某个查找算法天然只能属于其中一类，也不是 C 语言中的静态存储与动态存储。
:::

## 4. 关键字

**关键字（Key）**是数据元素中能够唯一标识该元素的某个数据项的值。查找通常依据关键字进行，并返回对应的数据元素。

例如，一条学生记录为：

```text
(学号=1001, 姓名=张三, 成绩=85)
```

其中：

- 完整的学生记录是**数据元素**；
- 学号、姓名、成绩都是**数据项**；
- 如果用学号唯一标识学生，那么 `1001` 是这条记录的**关键字**。

查找过程可以理解为：

```text
给定关键字 1001
        ↓
将它与记录的关键字进行比较
        ↓
定位学号为 1001 的记录
        ↓
返回完整的学生信息
```

引入关键字后，算法不必比较整条记录，只需比较用于查找的字段。后续代码中常见的 `key`，通常就是待查找的关键字。

::: tip 容易混淆的三个层次
- 数据元素：一条完整记录。
- 数据项：记录中的一个字段。
- 关键字：用于标识和查找该记录的数据项的值。
:::

## 5. 查找长度与平均查找长度

### 5.1 查找长度

一次查找的**查找长度**，是这次查找过程中进行的**关键字比较次数**。

例如，从头开始在数组中查找 `31`：

```text
[12, 25, 31, 47, 56]
```

比较过程为：

1. `12` 与 `31` 比较，不相等；
2. `25` 与 `31` 比较，不相等；
3. `31` 与 `31` 比较，相等。

因此，这次查找的查找长度为 3。

这里统计的是关键字的比较次数，不是程序执行的语句数，也不是内存访问总次数。

### 5.2 为什么需要平均查找长度

同一种算法查找不同元素时，比较次数可能不同。仍以从前向后的查找为例：

| 查找目标 | 比较次数 |
| --- | ---: |
| 12 | 1 |
| 25 | 2 |
| 31 | 3 |
| 47 | 4 |
| 56 | 5 |

最好情况和最坏情况只能反映两个极端。为了评价大量查找操作的平均水平，需要使用**平均查找长度（Average Search Length，ASL）**。

## 6. ASL 的公式与含义

设查找表中有 $n$ 个数据元素，则：

$$
\boxed{\mathrm{ASL}=\sum_{i=1}^{n}P_iC_i}
$$

其中：

| 符号 | 含义 |
| --- | --- |
| $n$ | 查找表中的数据元素个数 |
| $P_i$ | 查找第 $i$ 个数据元素的概率 |
| $C_i$ | 找到第 $i$ 个数据元素所需的关键字比较次数 |
| ASL | 平均查找长度 |

这个公式本质上是比较次数的**加权平均数**。一个元素被查找得越频繁，它对应的比较次数对平均值的影响就越大。

### 6.1 非等概率示例

假设某种算法查找元素 $A、B、C$ 分别需要：

$$
C_1=1,\qquad C_2=2,\qquad C_3=3
$$

三个元素被查找的概率为：

$$
P_1=0.5,\qquad P_2=0.3,\qquad P_3=0.2
$$

那么：

$$
\begin{aligned}
\mathrm{ASL}
&=P_1C_1+P_2C_2+P_3C_3\\
&=0.5\times1+0.3\times2+0.2\times3\\
&=\boxed{1.7}
\end{aligned}
$$

$1.7$ 表示大量查找操作平均需要进行 $1.7$ 次关键字比较，并不表示某一次查找真的可以比较 $1.7$ 次。

### 6.2 等概率时的简化

如果每个元素被查找的概率相同，则：

$$
P_i=\frac{1}{n}
$$

所以：

$$
\boxed{\mathrm{ASL}=\frac{1}{n}\sum_{i=1}^{n}C_i}
$$

也就是直接对各元素的比较次数求算术平均。

例如，五个元素的比较次数依次为 $1,2,3,4,5$：

$$
\mathrm{ASL}=\frac{1+2+3+4+5}{5}=\boxed{3}
$$

## 7. 学习 ASL 时的注意事项

::: warning 常见错误
1. ASL 是关键字比较次数的平均值，不等同于时间复杂度的定义。
2. 只有各情况等概率时，才能直接求算术平均；否则必须按概率加权。
3. 计算前应分清讨论的是查找成功还是查找失败，两者的概率模型和比较次数可能不同。
4. 即使面对同一张查找表，不同查找算法的 $C_i$ 不同，ASL 也可能不同。
:::

## 8. 本节知识关系

```text
查找
├─ 在哪里查：查找表
│  ├─ 只查询：静态查找表
│  └─ 还要插入、删除：动态查找表
├─ 根据什么查：关键字
└─ 怎样评价效率
   ├─ 单次：查找长度（关键字比较次数）
   └─ 多次平均：ASL = Σ PiCi
```

掌握这些概念后，后续学习顺序查找、折半查找等算法时，就可以统一回答：算法如何组织查找过程，以及它平均需要进行多少次关键字比较。
